# Matrix: изменения и проверка

Статус этого документа: инструкция, **не runtime PASS**. Результаты сборки,
эмулятора и проверки настоящего проигрывателя записываются отдельно.

## Область изменений

- **Настройки:** `SettingsTransfer` и `SettingsTransferDialog` добавляют сохранение
  JSON в собственный каталог приложения, проверку чтением и SHA-256, список копий
  и подтверждение импорта. Системный выбор документа предлагается при наличии
  доступного picker; отсутствие picker не объявляется успешным экспортом.
  Импорт переносит четыре группы preferences, проверяет формат/типы/размер,
  поддерживает rollback; синхронизация WebView выполняется через существующий
  MainActivity. Локальные копии принадлежат конкретному package: другой package
  не получает доступ к ним автоматически. SHA-256 проверяет целостность,
  но не шифрует содержимое.
- **MatriX:** статус и четыре действия находятся в одном прокручиваемом списке.
  Restart/очистка RAM-кэша сериализованы. Операции управляют только собственным
  дочерним процессом; внешний совместимый сервер разрешено использовать,
  но его restart/очистка не объявляются успешными. Собственный нездоровый процесс
  остаётся перезапускаемым. Очистка отклоняется при включённом или неизвестном
  дисковом кэше; дисковые данные не удаляются.
- **Серии:** ASK/AUTO/OFF, AUTO через 10 секунд; переход начинает следующую серию
  с нулевой позиции, включая её сохранённую timeline. Уход в фон отменяет prompt
  и завершает соответствующий completed state. Устаревшая финализация не очищает
  новый playback state. Последний элемент не запускает новую серию; загрузка
  следующего сезона не добавлена. Ручной выход после 96% по-прежнему считается
  завершением.

## Ручная сборка без публикации

Нужны Android SDK 34, совместимый JDK и штатный Gradle wrapper. Для подписанного
Matrix APK нужна разрешённая конфигурация release signing и соответствующий ключ.
Package ID и сертификат определяют возможность обновления установленного APK;
переименование файла этого не меняет.

Основной ключ Matrix хранится **вне Git** в
`%USERPROFILE%/.android/lampa-matrix-signing`. Сохранить этот ключ для всех
последующих обновлений; keystore и данные доступа в репозиторий не добавлять.
Целевая версия: `1.13.3`, versionCode `567`. SHA-256 нового сертификата:
`2177D53274D54D8296D333187F0097BA4AF128569A069FACE238BFD58819AE5E`.
`updateCertificateSha256` должен совпадать с сертификатом подписанного APK.

Старую установку с другим сертификатом можно заменить только удалением и новой
установкой после проверенного экспорта нужных настроек; это не обновление поверх
старого APK. Данные удаляемого package требуют отдельного восстановления.
Автообновления Matrix отключены до появления feed с APK нового сертификата:
Updater выбирает предложения по semver тега, а code/подпись проверяет после
скачивания. Будущие обновления должны сохранять ключ и иметь возрастающий code.

```sh
./gradlew :app:assembleFullMatrix
./gradlew :app:assembleLiteNextTest :app:assembleLiteNextTestAndroidTest :fakeplayer:assembleDebug
```

Не создавать/push release-тег ради проверки: существующий
`.github/workflows/android.yml` запускает `assembleRelease` и публикацию RuStore
для `top.rootu.lampa`. Приведённые команды собирают конкретные локальные варианты.

## Изолированная проверка

`testBuildType = nextTest`: целевой package `top.rootu.lampa.nexttest`, test package
`top.rootu.lampa.nexttest.test`. Отдельный `:fakeplayer` использует
`top.rootu.lampa.fakeplayer`; маршрутизация протокола Just Player включена только
в nextTest. Fake возвращает контролируемый completion для `example.invalid`;
это не проверка декодирования, TorrServe-потока или EOF настоящего Just Player.

В nextTest отключены автоматический запуск и восстановление встроенного сервера,
поэтому эти проверки не управляют установленным внешним TorrServe.
Установить три собранных тестовых APK на тестовое устройство, выбрав его
serial явно. Не запускать полный набор против пользовательской установки:
next-episode тесты очищают preferences своего тестового package; lifecycle-тесты
сервера имеют отдельные побочные эффекты. `IsolatedTestRunner` требует точный
target package и явный whitelist классов, исключающий lifecycle-тесты сервера:

```sh
adb -s "$TEST_SERIAL" shell am instrument -w -r -e class top.rootu.lampa.SettingsTransferTest,top.rootu.lampa.MatrixControlsTest,top.rootu.lampa.NextEpisodeJustPlayerTest top.rootu.lampa.nexttest.test/top.rootu.lampa.IsolatedTestRunner
```

Покрытие: перенос/повреждение копий; состав меню и ограничения ownership/cache;
ASK/AUTO/OFF, отсутствие запуска раньше 10 секунд, последняя серия, фон,
сброс позиции и гонка отложенной финализации. Отдельно фиксировать build PASS,
instrumentation PASS и реальные сценарии на TV; одно не заменяет другое.
ASK-тест проверяет фактическую UI-иерархию диалога и listener кнопки через
`performClick()`; фокус и управление настоящим пультом требуют отдельной проверки.
